# HDMI 48 kHz 音频测试音

在现有三张 BMP 图片切换与轮播工程中加入 HDMI 数据岛音频。
工程仍为 `HDMI_EX4_OSD.al`，顶层仍为 `hdmi_slideshow_top`，无需新增管脚。
按键、SD 卡 LBA、SDRAM 帧缓存和竖线修复保持不变。

## 输出参数

| 项目 | 设置 |
| --- | --- |
| 视频 | 640×480，800×525 总时序，60 Hz |
| 像素 / 串行时钟 | 25.2 MHz / 126 MHz DDR |
| 音频 | 48 kHz，双声道 LPCM，左右同音 |
| 测试音 | 1 kHz 正弦，16-bit 有效精度，峰值 4096，约 -18 dBFS |
| HDMI 音频传输字 | 24-bit，16-bit 样本左对齐，最低 8 位为 0 |
| 音频时钟恢复 | N=6144，CTS=25200 |

本版本不读取 WAV/MP3，不输出原图片附带音轨，也不实现音频解码。
它完成图片和内建测试音共同输出，而不是带时间戳的电影唇音同步。
显示器、电视或接收机必须支持 HDMI 音频；DVI 转接通常不传音频。
没有内置扬声器时，需要显示器音频输出或 HDMI 音频提取器。

## 同步机制

所有音频逻辑在像素时钟域内工作，每 525 个像素时钟产生一个音频样本：

```text
25,200,000 / 525 = 48,000 samples/s
48,000 / 60 = 800 samples/video frame
Fs = Fpixel × N / (128 × CTS) = 48,000 Hz
```

因此没有独立音频振荡器带来的长期音视频漂移。
加载阶段持续发送合法的静音 PCM 和元数据，接收端可提前锁定；
首图显示启用后的第一个可见帧开始启用正弦波。手动切图或轮播不会
重启音频相位，不会为了换图反复中断音频包。显示错误后后续采样变为静音；
接收端缓冲中仍可能残留几毫秒声音。
声音的实际到达时间仍受显示器/电视内部音频缓冲影响，未进行外部实测延迟校准。

## HDMI 包和行时序

`rtl/hdmi_audio_tx.v` 替代顶层中的三个直接 TMDS 编码器实例，内部继续调用
原编码器处理可见 RGB，沿用 `tmds_serializer_eg4.v` 进行串行输出。

| 水平坐标（0 起） | 输出内容 |
| --- | --- |
| 0–639 | 有效视频，仅有效视频行；垂直消隐行发送控制符 |
| 640–643 | 控制符 |
| 644–651 | 8 像素数据岛前导 |
| 652–653 | 数据岛前保护带 |
| 654–749 | 三个连续的 32 像素包 |
| 750–751 | 数据岛后保护带 |
| 752–789 | 控制符 |
| 790–797 | 若下一行有效：视频前导；否则控制符 |
| 798–799 | 若下一行有效：视频保护带；否则控制符 |

每个数据岛发送音频样本包、ACR 时钟恢复包、AVI InfoFrame、Audio InfoFrame
或空包。音频样本通过 16 项同步 FIFO 排队，每包最多装四个双声道样本。
每 32 行发送一次 ACR；每帧发送一次 AVI 和音频 InfoFrame。
每个包包含 24-bit 头的 BCH 和四个 56-bit 子包的 BCH 校验；
音频附带 IEC60958 通道状态、192 帧块起始标记及奇偶校验。
HDMI/DVI 差异不仅是 RGB 编码，不能删掉前导、保护带或音频校验。

这是固定模式发送器，不实现 EDID/DDC 能力协商、HPD 管理、HDCP、CEC 或音量控制。
当前输出包括真实 HDMI 数据岛，不应再称作“仅视频 DVI 输出”。

## 编译和下载

1. TD 4.6 打开 `HDMI_EX4_OSD.al`，在工程目录执行 `source build_ex4.tcl`。
2. 查看当前 `HDMI_EX4_OSD_timing.rpt`，确认布局布线和时序结果。
3. 执行 `source generate_ex4_bit.tcl`，生成根目录 `HDMI_EX4_OSD.bit`。
4. SD 卡使用原三张 BMP 和原地址。连接真正的 HDMI 线到有音频能力的显示器，
   下载新 bit 并复位。听音前先将接收端音量调低。
5. 加载完成后应显示图片并听到左右同声的连续 1kHz 测试音。
   验证 KEY12/13 切图、KEY14 轮播时声音保持连续。

LED 亮表示已启用显示且未捕获图像加载、视频欠载或音频 FIFO 溢出错误。
LED 不提供显示器是否解码出声音的反馈。

如果有图无声：先检查显示器是否自带扬声器、HDMI 输入是否被静音、
音频输出是否选中该 HDMI 端口，并排除 DVI 转接。若仍无声，请提供
显示器型号、LED 状态、连接方式；软件仿真不能代替真实接收端互操作测试。

## 回归验证

新增：`sim/run_audio_test.ps1`、`sim/test_hdmi_audio.cpp`。
需要 Verilator 和 MSVC，脚本参数与现有测试一致：

```powershell
./sim/run_audio_test.ps1 -VerilatorRoot 'C:/tools/verilator' -VsDevCmd 'C:/path/to/VsDevCmd.bat'
```

测试反向解码像素域三路 10-bit 输出符号，在 62 帧中逐个核对：

- 49,600 个生成样本及严格 525 时钟采样间隔；末尾允许一个尚未发送样本。
- 启音、静音和连续正弦样本，左右声道一致，顺序无丢失/重复。
- 192 帧通道状态、块起始标志、样本奇偶校验、包头和子包 BCH。
- ACR 的 N/CTS、InfoFrame 校验和及发送频率。
- 前导/保护带/消隐同步位以及整个有效区的 RGB TMDS 编码。

此测试验证符号层协议，不是 HDMI 认证测试，不覆盖实际线缆信号完整性、
接收端音频缓冲延迟或模拟扬声器波形。物理串行器保持原实现。
最终有声、无白条、切图音频连续等结果需要新版上板确认。

HDMI 包布局、TERC4 和 BCH 实现参考 hdl-util/hdmi，MIT 声明已保留，
见 `THIRD_PARTY_NOTICES.md` 和 `LICENSES/hdl-util-hdmi-MIT.txt`。
